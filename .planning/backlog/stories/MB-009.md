# MB-009: Clean architecture and hexagonal application boundaries

## Outcome

Keep the existing API and PostgreSQL behavior while isolating the application core from frameworks and concrete sibling modules.

## Acceptance criteria

1. Domain and application code have no Spring, JDBC, HTTP or adapter dependencies.
2. Typed use cases accept explicit operation context and return application views.
3. Controllers use input ports. Booking integrates through consumer-owned output ports.
4. The composition root applies transaction decorators and context/security annotations.
5. Aggregate state rules, creation, recurrence and room matching use tested domain/application policies.
6. Architecture rules run in CI. Existing database and API workflows remain compatible.
